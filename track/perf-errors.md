# 性能分析与错误监控

「性能分析」用五项网页性能指标看页面加载和交互快不快。「错误监控」把前端报错按指纹归并，列出每一组的次数和影响的会话。

两个页面都在「埋点分析」菜单下，进页面先选应用和时间范围。

![性能分析页，上面是五张指标卡和阈值说明，下面是分位明细表](/readme/track-perf.png)

## 性能指标和评级

指标由 SDK 的性能插件采集，页面第一次切到后台或关闭时上报，每项指标一条。采集方式见[插件](/track/plugins#性能指标)。

| 指标 | 含义 | 良好 | 差 |
| --- | --- | --- | --- |
| LCP | 最大内容绘制 | 不超过 2500 毫秒 | 超过 4000 毫秒 |
| INP | 交互到下一次绘制 | 不超过 200 毫秒 | 超过 500 毫秒 |
| CLS | 累积布局偏移 | 不超过 0.1 | 超过 0.25 |
| FCP | 首次内容绘制 | 不超过 1800 毫秒 | 超过 3000 毫秒 |
| TTFB | 首字节时间 | 不超过 800 毫秒 | 超过 1800 毫秒 |

评级看 P75，也就是四分之三的样本不超过的那个值。P75 落在两条线之间时评为「待改进」。

指标卡上的大数字是 P75，旁边是评级，下面是样本数。样本数是时间范围内收到这项指标的条数。

「分位明细」表列出每项指标的样本数、均值和三个分位数。P75 和 P95 按同一套线标颜色。

### 只看一个页面

在筛选框里填路由模板，按回车或点「查询」，只统计这个页面的样本。

要填完整的路由模板，比如 `/order/:id`。页面没有路由模板时填实际路径。

### 数值是估算的

分位数和均值不是逐条样本算出来的。后端把样本按下面的分界点分组计数，再在组内按比例估算。

| 指标 | 分界点 |
| --- | --- |
| CLS | 0.01 0.025 0.05 0.1 0.25 0.5 1 |
| 其余四项，单位毫秒 | 100 250 500 1000 2500 5000 10000 30000 |

样本少的时候偏差大。只有一个 1200 毫秒的样本时，P75 显示成 `2125ms`。

超过最后一个分界点的样本按这个分界点算。所以毫秒指标最大显示 `30000ms`，CLS 最大显示 `1.000`。

## 错误监控

列表每个错误指纹一行，按最近发生的时间从新到旧排。指纹怎么算见[插件](/track/plugins#错误)。

| 列 | 说明 |
| --- | --- |
| 错误摘要 | 这一组里最近发生的那条错误的信息 |
| 次数 | 时间范围内这一组错误的条数 |
| 影响会话 | 出现过这一组错误的会话数 |
| 首次发生 | 时间范围内第一次收到的时间，不是历史上的第一次 |
| 最近发生 | 时间范围内最后一次收到的时间 |

点一行的查看按钮打开「错误详情」。上面是指纹、总次数和影响会话数，下面是这一组的每一条错误，新的在前。

![错误详情，展开的一条错误里有页面、会话、堆栈和上下文](/screenshots/track/track-error.png)

展开一条错误能看到这些内容：

| 项 | 说明 |
| --- | --- |
| 页面 | 出错时的页面路径和路由模板 |
| Release | 上报这条错误的应用版本，初始化 SDK 时用 `release` 设置 |
| 会话 | 会话 ID 和访客的匿名 ID |
| 会话回放 | 这个会话有录制时出现「回放」，点开直接播放 |
| 事件ID | 这条错误事件的 ID |
| 堆栈 | 上报上来的原始堆栈 |
| 还原 | 「还原堆栈」按钮，只有带 Release 的错误才有 |
| 上下文 | 这条错误事件的全部属性 |

要把错误交给人跟进、标记已解决，用[错误问题单](/track/error-issues)。

## 还原堆栈

线上的脚本是压缩过的，堆栈里的行列号对不上源码。上传构建时生成的符号表后，可以换算回源文件的位置。

<div class="ms-steps">

### 初始化 SDK 时设置 `release`

每个版本用一个不同的值，比如构建时的版本号。写法见[安装与初始化](/track/install#配置项)。

### 上传这个版本的符号表

在「接入管理」的「符号表」页签上传构建产物里的 `.map` 文件，Release 填同一个值。见[接入管理](/track/apps#符号表)。

### 在错误详情里点「还原堆栈」

展开一条错误，点「还原」一行里的按钮。换算出来的源文件路径和行列号会高亮显示。

</div>

符号表按文件名匹配。堆栈里脚本的文件名加上 `.map`，就是要找的符号表文件名。

比如堆栈里是 `index-8f3a.js`，就找这个 Release 下的 `index-8f3a.js.map`。

换算在浏览器里做，页面会下载用到的符号表。一个 Release 最多取 100 个符号表文件来匹配。

还原不出来时，按钮的位置会显示原因：

| 提示 | 原因 |
| --- | --- |
| 该 Release 尚未上传符号表，上传符号表后可还原 | 这个应用的这个 Release 下没有符号表 |
| 堆栈帧未匹配到该 Release 的符号表文件 | 文件名对不上，或者符号表里查不到这个位置 |

## 错误告警

应用打开「错误告警」后，后端每收到一条带指纹的错误就按两条规则判断，命中就发站内信。

| 规则 | 什么时候发 |
| --- | --- |
| 新错误 | 一个指纹第一次出现时发一次，之后 7 天内不再按这条规则发 |
| 高频错误 | 同一个指纹 10 分钟内的次数达到「告警阈值」时发一次，这 10 分钟内不再发 |

告警阈值可填 1 到 1000，默认 10。开关和阈值在应用的编辑表单里，见[接入管理](/track/apps#应用管理)。

两条规则各判各的。阈值设成 1 时，一个新指纹的第一条错误会发两封。

站内信的标题是「埋点错误告警」。正文写明应用、错误指纹和命中的规则，并带错误监控页的链接。正文里的时间是 UTC。

收件人是应用所属租户里，角色编码为 `admin` 的角色下状态正常的用户。没有这样的用户时不发。

告警只发站内信。判断或发送失败只记日志，不影响错误入库。站内信在哪里看见[站内信与公告](/boot/features/message)。

## 数据多久更新

性能分析的结果在后端缓存 45 秒。错误列表和错误详情每次都查库，不缓存。

时间范围按后端收到事件的时间算，和[数据概览](/track/overview#数据多久更新)一样。

## 权限

| 权限 | 能做什么 |
| --- | --- |
| `sys:track-perf:list` | 打开性能分析 |
| `sys:track-error:list` | 打开错误监控，查看错误详情 |
| `sys:track-app:edit` | 还原堆栈。查符号表列表要这个权限 |
| `sys:track-replay:list` `sys:track-replay:view` | 在错误详情里看到会话回放入口并播放，两个都要有 |
| `sys:track-app:list` | 加载页面顶部的应用下拉 |

只能看到本租户的应用和数据。

## 接口

接口都在 `/system/track` 下面，都是 GET，要登录。

| 路径 | 权限 | 参数 |
| --- | --- | --- |
| `/vitals` | `sys:track-perf:list` | `appKey` `days` `routePath` |
| `/errors/page` | `sys:track-error:list` | `appKey` `days` `pageNum` `pageSize` |
| `/errors/detail` | `sys:track-error:list` | `appKey` `fingerprint` `days` `pageNum` `pageSize` |
| `/sourcemap/raw` | `sys:track-error:list` | `id` |

`days` 默认 7，可取 1 到 90。`pageSize` 默认 10，最大 500。

| 路径 | 返回 |
| --- | --- |
| `/vitals` | 有样本的指标各一项，字段是 `metric` `count` `avg` `p50` `p75` `p95` |
| `/errors/page` | 每行有 `fingerprint` `eventCount` `sessionCount` `firstTime` `lastTime` `message` |
| `/errors/detail` | 每行有 `eventId` `sessionId` `distinctId` `urlPath` `routePath` `time` `message` `release` `stack` `props` |
| `/sourcemap/raw` | 符号表文件的原文 |

`/vitals` 里 `cls` 的四个数值是实际值乘以 1000，比如 `100` 表示 0.1。其余指标的单位是毫秒。

`props` 是 JSON 字符串。时间都是毫秒时间戳。
