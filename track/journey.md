# 访问路径

「访问路径」看用户打开一个页面以后，下一步去了哪个页面，有多少到这里就没有再往下走。

页面在「埋点分析」菜单下。它按会话统计，不按人，也不按设备。

![访问路径页，上面是已选路径，下面每一列是下一步去的页面](/screenshots/track/track-journey.png)

## 和漏斗有什么不一样

| 对比项 | 漏斗分析 | 访问路径 |
| --- | --- | --- |
| 回答的问题 | 事先定好的几步，每一步有多少人做完 | 从一个页面出发，接下来实际去了哪 |
| 步骤 | 查之前先配好 | 边看边选，点哪一行就往哪走 |
| 步骤之间 | 中间可以夹着别的事件 | 要紧挨着，中间不能有别的页面 |
| 统计单位 | 人 | 会话 |
| 看的事件 | 任意事件 | 只看页面浏览 `$pageview` |

关键步骤已经清楚、想盯转化率，用[漏斗](/track/funnel-retention)。

还不知道用户是怎么走的、想找出意料之外的去向，用访问路径。

## 怎么算

| 规则 | 说明 |
| --- | --- |
| 会话 | 一次会话里的页面浏览按发生时间排成一串。会话结束后再来是另一次会话，路径不会接起来 |
| 页面 | 优先用路由模板，比如 `/order/:id`，同一类页面合成一个。没有路由模板时用实际路径 |
| 重复打开 | 连着几次都是同一个页面只算一次，比如刷新 |
| 步骤之间 | 要紧挨着。选了 A、B 两步，只算 A 之后紧接着就是 B 的会话 |
| 起点 | 每次会话只从起点页面第一次出现的地方往后看 |
| 时间范围 | 今天、近 7 天或近 30 天，从当地时区的 0 点算起 |
| 步数 | 一条路径最多选 5 步 |

路由模板要在初始化 SDK 时传 `router` 才有，见[安装与初始化](/track/install)。会话什么时候结束，见[数据概览](/track/overview)。

起点只看第一次，所以每一列的数都对得上：

- 一列里各个去向的会话数，加上「其他页面」和「没有下一步」，等于走到这一步的会话数。
- 点的那一行写着几，选中以后那一步就是几。

举个例子，一次会话先走了 A 到 C，后来又走了 A 到 B。选 A、B 两步时，这次会话不算。

会话跨过时间范围的起点时，只能看到范围内的那一段。

## 看一条路径

<div class="ms-steps">

### 选应用、时间范围和起点方式

都在页面顶部。应用和时间范围沿用其他埋点页面上次选的值。

### 在「起点」一列点一个页面

右边多出一列「第 1 步之后」，列出这些会话接下来去的页面。

### 接着点下一步

每点一行，右边再多一列。点同一列的另一行，这一步换成新选的页面，后面的步骤去掉。

</div>

每一列有这些内容：

| 内容 | 含义 |
| --- | --- |
| 列头的会话数 | 走到这一步的会话数。「起点」一列是时间范围内有页面浏览的会话数 |
| 每一行 | 下一步去的页面、会话数，和它占列头会话数的比例 |
| 其他页面 | 去向排不进列表的会话数。点「显示更多」，列表从 10 个变成最多 50 个 |
| 没有下一步 | 走到这一步以后，没有再打开别的页面的会话数 |

「其他页面」和「没有下一步」固定在每一列的底部，列表滚动时一直看得到。

页面顶部的「已选路径」列出选好的每一步：

- 每一步后面是走到这一步的会话数。从第二步起，还有它占上一步的比例。
- 选了两步以上时显示「走完整条路径」，是最后一步的会话数除以第一步的会话数。
- 点前面的某一步，回到那一步，后面的步骤去掉。点「清空」从头再来。

## 两种起点方式

| 起点方式 | 含义 | 适合看什么 |
| --- | --- | --- |
| 任意位置 | 路径可以从会话中间开始 | 用户到了某个页面以后去哪 |
| 从入口页开始 | 路径必须从会话的第一个页面开始 | 用户进站以后怎么走 |

「起点」一列在两种方式下的含义不一样：

- 「任意位置」列的是会话里出现过的页面。一次会话会算进好几个页面，各行加起来会超过总会话数。
- 「从入口页开始」列的是入口页。一次会话只有一个入口页，各行加上「其他页面」等于总会话数。

切换起点方式或时间范围时，已选的路径会留着，按新的条件重新统计。

有几点要知道：

- 数据来自页面浏览事件 `$pageview`。应用没有上报页面浏览时，这一页是空的。
- 已选的路径不会保存，刷新页面后要重新选。切换应用会清空已选的路径。
- 时间范围和其他埋点页面共用。在留存分析里选了近 14 天，这里也按近 14 天查。
- 结果在后端缓存 45 秒，条件不变时马上重查拿到的是同一份。
- 这一页直接查明细数据，所以时间范围最多 30 天。

## 权限

| 权限 | 能做什么 |
| --- | --- |
| `sys:track-journey:list` | 打开访问路径并查询 |
| `sys:track-app:list` | 加载页面顶部的应用下拉 |

只能查本租户的应用。

## 接口

接口是 `GET /system/track/journey`，要登录，权限是 `sys:track-journey:list`。

| 参数 | 说明 |
| --- | --- |
| `appKey` | 应用标识，必填 |
| `steps` | 已选的步骤，JSON 数组，比如 `["/","/list"]`。最多 5 个，相邻两个不能相同。不传表示还没选起点 |
| `days` | 默认 7，可取 1 到 30，超出范围报错 |
| `start` | `any` 或 `entry`，默认 `any` |
| `limit` | 列出多少个去向，默认 10。超过 50 时按 50 查，不报错 |

`steps` 用 JSON 数组，不用逗号隔开，因为页面地址里可以有逗号。放进地址时要做 URL 编码。

返回这些字段：

| 字段 | 说明 |
| --- | --- |
| `total` | 时间范围内有页面浏览的会话数 |
| `steps` | 已选的每一步，每项有 `page` 和走到这一步的 `sessions` |
| `next` | 下一步的去向，每项有 `page` 和 `sessions`，按会话数从多到少。还没选起点时是可以当起点的页面 |
| `ended` | 走完已选的步骤以后，没有下一步的会话数 |
| `others` | 去向排不进 `next` 的会话数 |
| `days` `start` | 实际生效的天数和起点方式 |
| `unit` | 统计单位，固定是 `session` |

选了步骤以后，`next` 的会话数之和加上 `ended` 和 `others`，等于最后一步的 `sessions`。
