# 行为验证码

登录、注册、忘记密码发码和发送短信验证码，默认都要先通过一道行为验证码。验证码是 boot 自带的实现，不依赖第三方服务。

这一页讲后端：题型、接口、配置和上线前要做的事。前端的交互见[管理后台的行为验证码](/pc/captcha)。

## 五种题型

| 题型 | 标识 | 用户要做的事 |
| --- | --- | --- |
| 滑块 | `SLIDER` | 把拼图块拖到缺口处，画面里另有假缺口 |
| 旋转 | `ROTATE` | 拖动滑条，把圆图转到正确的角度 |
| 文字点选 | `WORD_CLICK` | 按字序依次点一个 3–4 字的常用词语或成语 |
| 图标点选 | `ICON_CLICK` | 依次点 3 个图标 |
| 拼图还原 | `JIGSAW` | 还原 2×2 的拼图 |

- 默认五种全部启用。服务端从该租户启用的题型里随机出一种，前端不能指定。
- 题目全部在服务端校验。答案只存在题目记录里，校验一次即作废。
- 错误码、失败次数和锁定规则对所有题型相同。

## 接入流程

| 接口 | 说明 |
| --- | --- |
| `GET /auth/captcha/config?scene=&clientId=&tenantId=` | 是否需要验证，仅供前端提示 |
| `POST /auth/captcha/challenge` | 取底图与拼图块，有效期 `expireSeconds` |
| `POST /auth/captcha/verify` | 提交落点与轨迹（或键盘模式的按键次数），换取一次性 `captchaToken` |

一次完整的验证分四步：

1. 页面调 `config`，看当前场景要不要验证。
2. 要验证时调 `challenge` 取题，按响应里的 `type` 渲染题目。
3. 用户做完后调 `verify`，通过后拿到一次性的 `captchaToken`。
4. 把 `captchaToken` 放进业务请求体一起提交。

参数和令牌的规则：

- `scene` 取 `login`、`register`、`sms`（发送短信验证码）、`forget`。
- 取题时用 `inputMode` 声明输入方式，校验时必须一致：
  - `pointer`：鼠标或触屏；
  - `keyboard`：键盘。键盘题会返回 `keyboardStep`，按键次数要与落点对得上。
- `captchaToken` 用在四个接口的请求体里：
  - `/auth/login`、`/auth/register`；
  - `/auth/sms-code`、`/auth/forget-code`。
- 令牌只能用一次，并且必须与取题时的场景、客户端、租户一致。
- 服务端会自己判断是否需要验证，不以 `config` 的结果为准。

## 取题规则

- 前端按响应里的 `type` 渲染题目，请求里传 `type` 无效。
- `config` 返回的 `type`：启用两种及以上题型时为 `RANDOM`，否则为具体题型名。
- 请求头 `Accept-Language` 只决定提示语言，不影响出哪种题型。
  - 英文时，图标点选的提示名用英文。
- 点选题按出题时的底图尺寸判定。题目有效期内改尺寸配置，不影响已出的题。

### 键盘模式

- 键盘模式（`inputMode: keyboard`）只从该租户已启用的滑块和旋转里选题。
- 两者都没启用时，键盘取题返回 `40015`（未启用无障碍验证方式），不会改出其他题型。
- 键盘取题先计单 IP 限流（`rate-limit.keyboard-challenge-per-minute`），再判断是否返回 `40015`。
- 被 `40015` 拒绝的请求也计入这个限流。
- 按租户的键盘取题数只在 Redis 里计数，不写审计。
- 只有 `40015` 会写审计日志，同一租户、同一 IP 10 分钟内只记一条。

## 配置

完整键名与默认值见 `application.yml` 的 `mugsun.captcha`。

### 开关、存储和限流

```yaml
mugsun:
  captcha:
    enabled: true          # 全局开关
    store: redis           # redis | memory；memory 仅单机开发，prod 下启动失败
    slider:
      tolerance-px: 6      # 落点容差（底图原始像素，底图 320×180）
      expire-seconds: 120  # 挑战有效期
      token-expire-seconds: 120
      decoy-count: 2       # 假缺口数（与真缺口同轮廓）0–3
      keyboard-step-px: 4  # 键盘模式每次按键移动的原始像素
      bind-ip: false       # 令牌强制绑定 IP / UA（关闭时只记录）
      bind-ua: false       # prod 默认 true
    background:
      dir: classpath:captcha/bg/   # 也可 file:/opt/mugsun/captcha-bg/
      rotate: random               # random | round-robin
      reload-seconds: 600          # 目录重扫间隔，0 = 只在启动时加载
    rate-limit:
      challenge-per-minute: 30     # 单 IP 每分钟取题
      verify-fail-max: 5           # 10 分钟内失败次数，超过锁定 10 分钟（键盘模式 3 次）
      global-challenge-per-second: 200   # 全局每秒取题上限（Redis 存储时跨节点共享）
      sms-phone-per-day: 10        # 发送短信：单手机号每天
      sms-ip-per-hour: 20          # 发送短信：单 IP 每小时
      sms-phone-per-minute: 5      # 发送短信短窗口：单手机号每分钟（仅令牌核销成功后计数，自动恢复）
      sms-ip-per-minute: 30        # 发送短信短窗口：单 IP 每分钟（所有请求计数，含没带令牌的）
```

### 题型参数

```yaml
mugsun:
  captcha:
    # 租户没单独设置时启用的题型，每次随机出一种
    default-types: [SLIDER, WORD_CLICK, ROTATE, ICON_CLICK, JIGSAW]
    rotate:
      dir: classpath:captcha/rotate/
      piece-size: 160
      tolerance-deg: 10
      keyboard-step: 5
      track-replay-window-seconds: 600   # 同一条拖动轨迹在窗口内只能用一次，≤0 关闭
    click:
      count: 3                    # count 和 decoys 只用于图标点选
      decoys: 2
      min-radius-px: 22
      min-duration-ms: 400
      max-duration-ms: 30000
      words-file: ""              # 私有词库；留空用内置词库
      seed-warp-strength: 0.14    # 图标点选每题的网格形变强度，0 为关闭
    jigsaw:
      rows: 2
      cols: 2
    icon-dir: classpath:captcha/icons/   # 图标目录，须含 manifest.json 与 <slug>.png
    render-max-concurrent: 16            # 本节点同时出图上限，超限返回 40012；≤0 不限
    render-acquire-timeout-ms: 200       # 等待出图许可的最长毫秒数，超时返回 40012
    rate-limit:
      keyboard-challenge-per-minute: 10  # 键盘模式单 IP 每分钟取题上限
```

### 租户开关 {#tenant-switch}

每个租户默认开启，新建的租户也一律开启。平台超管可以在管理后台里改某个租户的设置，见[给租户单独设置](/pc/captcha#tenant)。

也可以调用 `POST /system/tenant/captcha`：

```json
{ "id": 1, "enabled": true, "types": ["SLIDER", "ROTATE"] }
```

- `id` 是租户主键。`enabled` 传 `false` 就关闭这个租户的验证码，其他租户不受影响。
- 操作会写入审计日志。多节点部署时，其他节点最多 60 秒后生效。
- `types` 设置该租户启用的题型，至少一种，取值只能是上面五种。
  - 不传 `types` 则不改；
  - 传 `null` 或 `[]` 清回平台默认（`default-types`）；
  - 没设置过的租户使用 `default-types`。
- 设置里不含 `SLIDER` 和 `ROTATE` 时仍会保存，但响应 `data.warning` 会提示键盘用户将收到 `40015`。
- 设置保存在 `sys_tenant.captcha_types`（迁移 `V10__tenant_captcha_types.sql`）。
- 发送短信验证码与租户无关，只看全局开关，并且有单手机号每天、单 IP 每小时的频控。
- 客户端开关（`sys_client.captcha_enabled`）不参与判定，因为 clientId 由调用方填写。

::: warning 关闭验证码会去掉防爆破保护
设 `mugsun.captcha.enabled=false` 或关闭某个租户后，该租户的登录、注册和忘记密码发码不再要求人机验证。

这时只剩登录失败锁定和频控。只在排查问题或前端尚未升级时临时关闭。
:::

## 容差和计时

容差按「普通人 1–2 秒能过」设定。

### 旋转 {#rotate-tolerance}

- 容差 ±10°。服务端施加的角度是 `keyboard-step` 的整数倍，并且在 30°–330° 之间。
- 旋转以提交的角度判对错。拖动轨迹用来判断是不是人在操作，另外还要满足一个条件：
  - 首末位移换算出的角度 a_t = 位移 ÷ 显示宽度 × 360°；
  - 0.5 × 提交角度 − 10° ≤ a_t ≤ 提交角度 + 10°。
- 前端可以做低速精调，低速时位移按不低于 0.5 的倍率累加。管理后台用的是 0.6 倍。
  - 轨迹的 x 要记累加后的逻辑位置，不是指针的原始坐标。
- 同一条轨迹 10 分钟内只能用一次，重放会校验失败。
- 旋转容差没有收得更窄：触屏松手通常会偏 3–8 像素，而连续失败会锁定，收紧容易误锁。
- 也不按 `pointerType` 区分容差，因为它由客户端自报。
- 盲猜的风险靠失败锁定、限流和每题底图随机化来控制。

### 点选和拼图

- 点选的命中半径是字号或图标边长的 0.75 倍，至少 22 像素。
- 点选元素两两之间的距离，不小于两个命中半径之和再加 6 像素。
- 点选和拼图的操作时长限制在 0.4–30 秒，从第一次操作算起。
- 打开题目到第一次操作之间不计时，只受题目有效期约束。
  - 有效期是 `slider.expire-seconds`，默认 120 秒；过期后校验返回 `40010`。

## 每道题的随机化

- 底图和旋转图随机缩放、裁切、镜像和调色。
- 拼图块另加噪声和轻微色偏（每块 ±4），开局至少 3 块不在原位。
- 滑块的假缺口与真缺口轮廓相同，默认 2 个。
- 图标点选的图标不垫白色圆盘，改为贴合轮廓的投影和细描边，干扰线画在图标下面。
- 图标点选默认对公开库 PNG 做每题 seed-warp 网格形变（含描边微扰）。
- 提示条与画布对同一 slug 使用同一 seed，抗公开库模板匹配。
- 文字点选里笔画少于 3 的字（如「一」「十」「人」）只旋转 ±15°。

## 上线前换成私有素材

默认的底图（12 张）、旋转图（16 张）和图标（44 个）随开源仓库公开。攻击者可以拿公开原图和题图做差定位缺口，或预先做旋转、图标的答案表。

- 生产部署请把 `background.dir`、`rotate.dir`、`icon-dir` 都换成自己的目录，并定期更换。
  - 目录可以用 `file:` 或 `classpath:` 前缀。
- 文字点选用 `click.words-file` 换成私有词库。
- `prod` 下仍在使用仓库自带素材时，启动日志会给出警告。
  - 按目录或文件哈希判断；
  - 没有配置 `click.words-file` 时，同样计为使用自带素材。

### 背景图

- 放 jpg 或 png，推荐 640×360（16:9），单张不超过 200KB，至少 20 张。
- 避免大面积纯色。目录为空时使用纯色占位。
- 只用自有或允许商用的图片，并在目录里用 `SOURCES.md` 记下来源。

### 词库

- 词默认来自内置词库：自行整理的 477 条常用词语和成语，只用《通用规范汉字表》一级字。
- 内置词库随仓库公开，攻击者识别文字后可以用词典纠错。
- 私有词库每行一个 3–4 字的词，`#` 开头为注释。
- 词里的字必须在内置字体子集里，否则该词会被忽略，并在启动日志里警告。
- 私有词库读不到或没有可用词时，回落内置词库。
- 画面里另有 1–2 个干扰字，优先取形近字或同音字。点到干扰字或顺序不对即不通过。
- 文字用内置的思源黑体子集（SIL OFL 1.1）在服务端渲染并加干扰。

### 图标

- 图标目录须带 `manifest.json`，字段有 `slug`、`name_zh`、`name_en` 和 `confusable`。
  - 缺 `name_en` 时，英文界面退回中文名。
- 外形容易混淆的图标不会出现在同一题里。
- 图标清单缺失或损坏时，启动日志会给出警告，图标点选自动停用，不影响其他题型。
- 这时某租户如果只启用了图标点选，取题返回 `40016`（验证方式暂不可用），不会改出滑块。
  - 这种情况会写一条审计日志，同一租户、同一 IP 10 分钟内只记一条。

## 辅助题型的局限

旋转和图标点选是辅助题型，只能部分抵御自动求解，不能当作唯一防线。

### 旋转 {#rotate-limits}

- 旋转题在平台默认的随机集里。
- 圆孔用不透明纯色填充，圆图另做调色、模糊、噪点和边缘羽化。按孔内像素比对的求解器已经失效。
- 按圆图边缘与孔外图案的连续性求角，仍有约一半的题能落在 ±10° 内。
- 要配合失败锁定和限流，并同时启用其他题型。
- 租户只启用 `ROTATE` 时仍会保存，但响应 `data.warning` 会给出提示。

### 图标点选

- 图标库（含 `manifest.json`）随仓库公开。
- 渲染默认对每题做 seed-warp 网格形变，让公开原图与题图不再重合，抬高模板匹配的难度。
- 形变强度的配置键是 `mugsun.captcha.click.seed-warp-strength`，默认 `0.14`。
  - 设为 `0` 关闭形变；渲染侧的有效强度钳位在约 `[0, 0.35]`。
- 回归测试用模板匹配求解器，每次 200 题。
  - 三个图标全部点对约 0–1/200；超过 20% 时 CI 失败。
  - 这只说明能挡住这一类求解器。
- 要配合失败锁定和限流，并同时启用滑块或其他题型。生产环境请换成私有图标库。
- 租户只启用 `ICON_CLICK` 时仍会保存，但响应 `data.warning` 会给出提示。

### 随机多题型

五种题型随机出题时，攻击者可以反复刷新，等到最弱的题型再解，整体强度接近最弱的那一种。

介意这一点的租户，可以用[租户开关](#tenant-switch)的 `types` 只留下需要的题型。

## 错误码

错误码通过 HTTP 200 + `R.code` 返回：

| code | 含义 |
| --- | --- |
| `40010` | 题目已过期，重新取题 |
| `40011` | 未通过，重新取题（不提示具体原因） |
| `40012` | 尝试过多，`data.retryAfter` 秒后再试 |
| `40013` | 需要验证码，但请求没带 `captchaToken`，或令牌已用过、已过期、不属于这个场景或租户 |
| `40014` | 当前无需验证 |
| `40015` | 键盘模式取题，但该租户没有启用滑块或旋转（未启用无障碍验证方式） |
| `40016` | 该租户启用的题型此刻都不可用，例如只启用了图标点选而图标清单缺失 |

几个码的补充说明：

- `40012`：触发锁定的那次失败本身就返回 `40012`，如鼠标第 5 次、键盘第 3 次。
  - 校验失败时该 IP 已被锁定，也返回 `40012`，包括并发请求或另一种输入方式刚锁上。
  - 锁定期内，取题和校验都返回 `40012`。
- `40013`：HTTP 状态码是 200，前端按 `code` 重新弹出验证码。
- `40016`：请联系管理员，前端不要自动重试。
- 校验接口的请求体上限是 32KB（含分块传输），超限同样返回 HTTP 200 + `40011`。

## 忘记密码和发送短信

### 忘记密码

`/auth/forget-code` 不管账号存不存在，返回的都是同一句成功提示。

```text
如账号存在，验证码已发送至绑定邮箱
```

- 邮件是异步发送的，响应时间不随账号是否存在而变化。
- 下面几种情况返回的都是这句提示：
  - 账号不存在、未绑定邮箱；
  - 邮件通道未配置、下发失败。
- 具体原因只写服务端日志，避免有人借此判断账号是否存在或通道状态。
- 部署后请检查邮件通道，否则用户收不到验证码，却看到「已发送」。

### 发送短信

`/auth/sms-code` 按下面的顺序执行：

1. 检查单 IP 短窗口：每分钟 30 次，所有请求都计数，包括没带令牌的，60 秒后自动恢复。
2. 只读检查日配额（单手机号每天、单 IP 每小时），已超额时不消耗令牌。
3. 核销 `captchaToken`。
4. 检查单手机号短窗口：每分钟 5 次，只在令牌核销成功后计数。
5. 原子地「未超上限才计数」日配额。
6. 发送。

这样排的结果：

- 没带令牌或令牌无效的请求只计入 IP 短窗口，不计入手机号短窗口，也不占日配额。
- 所以别人无法替你把某个号码锁住，或把当天的配额刷光。
- 发送失败不退还配额，并写入审计日志。
- 超限一律返回 `40012` + `retryAfter`。
- 手机号先去空格和 `-`，再去 `+86`、`0086`、`86` 前缀。频控、发码与短信登录用同一个号码。

## Redis 键

验证码状态都在前缀 `mugsun:captcha:v2:` 下。`store: memory` 时，同名键在进程内。

| 键 | 用途 | 过期 |
| --- | --- | --- |
| `challenge:<captchaId>` | 题目（答案与绑定信息），校验时取出即删 | `expire-seconds` |
| `token:<captchaToken>` | 一次性令牌，业务接口取出即删 | `token-expire-seconds` |
| `rl:challenge:<ip>` | 单 IP 每分钟取题计数 | 60 秒 |
| `rl:keyboard:<ip>` | 单 IP 每分钟键盘校验计数 | 60 秒 |
| `rl:global:<秒>` | 全局每秒取题计数 | 2 秒 |
| `rl:sms-phone:<号码哈希>` / `rl:sms-ip:<ip>` | 发送短信日配额（核销成功后才计） | 1 天 / 1 小时 |
| `rl:sms-burst-phone:<号码哈希>` / `rl:sms-burst-ip:<ip>` | 发送短信短窗口频率限制 | 60 秒 |
| `fail:<pointer\|keyboard>:<ip>` | 失败计数 | `fail-window-seconds` |
| `lock:<ip>` | IP 锁定，剩余 TTL 即 `retryAfter` | `lock-seconds` |

IPv6 地址中的 `:` 写成 `_`。要手动解锁某个 IP，删掉它的锁定键：

```bash
redis-cli DEL 'mugsun:captcha:v2:lock:<ip>'
```
