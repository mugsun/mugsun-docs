# AI 辅助建模

在「系统管理 → 动态建表」里输入一段描述，系统给出一份可以编辑的表结构候选。候选确认后才会写入配置和建表，不会自动落库。

## 描述怎么写

首段写英文表名和中文说明，之后每段写一个字段：英文字段名、中文含义、类型词。段与段之间用分号、逗号、顿号或换行分隔。

```text
product_comment 商品评论；content 评论内容 文本，score 评分 整数，author 作者 文本，comment_time 评论时间 日期
```

类型词决定 Java 类型和表单控件：

| 类型词 | Java 类型 | 控件 |
| --- | --- | --- |
| 文本、内容、备注、描述 | `String` | 多行文本 |
| 金额、价格、小数 | `BigDecimal` | 数字 |
| 长整数、编号 | `Long` | 数字 |
| 整数、数量、评分 | `Integer` | 数字 |
| 时间、日期时间 | `LocalDateTime` | 日期时间 |
| 日期 | `LocalDate` | 日期时间 |
| 开关、是否 | `Integer` | 开关 |
| 状态、类型、下拉 | `String` | 下拉 |

没有类型词的字段按 `String` 和输入框处理。`id`、`create_time`、`update_time`、`is_deleted` 四列会自动补上。

## 接入大模型

后端带 AI 模块（默认的 `full` 构建已包含），且 AI 模块已启用、配好了对话模型时，描述会先交给大模型。

这时可以直接写中文句子，例如「记录门店每天的客流量和销售额」。

大模型使用 AI 中心里标为默认的对话模型；没有默认模型时取最新启用的一个。

大模型返回的表名或字段名不合规、调用失败或没有配置模型时，系统改用上面的规则解析。规则解析要求写英文标识符，只写中文会提示「至少描述表名与一个字段」。

::: tip
页面上的说明文字只描述规则解析。接入大模型后，中文句子同样可以生成候选。
:::

## 确认和建表

候选出现后，表名、说明、每个字段的名称、类型、列表、必填、查询都可以改，也可以加字段或删字段。

- 「确认并建表」保存表配置并立即建物理表。建表失败时，表配置一起回滚。
- 「仅保存配置」只保存表配置，之后在「动态表管理」里建表。

表名和字段名必须以小写字母开头，只含小写字母、数字和下划线。

下面这些表受保护，不能建或重建：

- 以 `sys_`、`flyway_`、`flow_`、`qrtz_`、`act_`、`biz_`、`help_`、`viz_`、`ai_` 开头的表；
- `gen_table` 和 `gen_column`。

## 管理已建的表

「动态表管理」列出所有保存过的表，每行有五个操作：

- 字段配置：改字段。改列名按 RENAME 处理，加字段按 ADD 处理，数据保留。
- 预览 DDL：显示将要执行的语句，不执行。
- 建表：物理表不存在时创建。
- 增量同步：按字段配置执行 ADD 和 RENAME，数据保留。
- 强制重建：删表后重建，表里的数据全部丢失。

## 看效果

打开「系统管理 → 动态建表」，在「规则建模」里粘贴上面的示例描述，点「生成候选」。

![规则建模生成的候选](/screenshots/codegen/gen-modeling-draft.png)

`comment_time` 这一段同时含「时间」和「日期」，系统先匹配到「时间」，所以类型是 `LocalDateTime`，说明只剩「评论」。

在表格里把它改成需要的类型和说明即可。

点「确认并建表」后切到「动态表管理」，`product_comment` 出现在列表里。

![动态表管理](/screenshots/codegen/gen-modeling-manage.png)

也可以直接调接口。`/system/gen/ai/draft` 只返回候选，不写库：

```bash
curl -s -X POST http://localhost:8080/system/gen/ai/draft \
  -H "Authorization: $TOKEN" -H 'Content-Type: application/json' \
  -d '{"description":"product_comment 商品评论；score 评分 整数"}'
```

响应的 `data` 里有 `table` 和 `columns` 两部分。

把它们原样放进 `/system/gen/ai/confirm` 的请求体，并加上 `"build": true`，就会保存配置并建表。
