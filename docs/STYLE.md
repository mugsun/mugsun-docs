# 文档写作规范

docs.mugsun.com 的中英文页面都按这份规范写。依据是 2026-10 对 VitePress、Vue、Element Plus、Vite、Astro、Supabase 等 10 个文档站的实测对比。

本文件放在 `docs/` 下，已加进 `srcExclude`，不会生成站点页面。

## 硬指标

| 项目 | 要求 |
| --- | --- |
| 首页分区 | 最多 8 个，每个分区一个标题、一段引言（最多两句） |
| 首页卡片 | 标题不超过 12 个字，正文一句话、不超过 50 个字 |
| 快速开始字量 | 1000 字以内 |
| 快速开始代码占比 | 40–70%（代码字符数 ÷ 正文字符数） |
| 段落长度 | 一段不超过 3 行，约 60 字；最长不超过 80 字 |
| 提示框 | 一页最多 3 个，每个一两句话 |
| 截图 | 一页一到两张（首页的截图窗口除外） |

字数按中文页面计。英文页和中文页保持同样的结构和句数。

## 12 条规范

1. 首页是落地页，分区和顺序固定，见 `index.md` 的 frontmatter。适合与不适合、模块表放「介绍」页。
2. 首屏标题不超过 16 个字，引言最多两句、不超过 60 个字。写清楚它是什么、给谁用。
3. 首页不写小版本号。技术栈只写在「仓库」分区的标签里，其他分区不堆技术名词。
4. 快速开始第一屏就要有能复制的命令，命令前面最多两句话。
5. 快速开始控制在 1000 字以内，代码占一半左右。超出的内容拆到「部署」「配置」「常见问题」。
6. 一段不超过 3 行，一句只讲一件事。
7. 提示框（tip、warning）一页最多 3 个。可以不展开的内容放进 `::: details`。
8. 多种包管理器或多种写法用 `::: code-group`，不要连续摆几个代码块。
9. 截图只用真实界面。概述页开头放最能代表这个模块的一张，步骤里放做完这一步应该看到的样子。组件页用实时示例代替截图。
10. 操作页的标题写读者要做的动作，比如「安装」「启动后端」。概述页的标题写读者要找的内容，比如「有哪些页面」。不写「设计取舍」「能力」「全景」。
11. 正文不写 PR 编号、升级前后的口径差异、迁移 SQL。这些放「更新日志」和「升级指南」。
12. 禁用的写法：
    - 自造词，比如竖切、在位、装配、底座；
    - 「**加粗口号。** 解释」连着排；
    - 「不是……而是……」；
    - 用中点「·」或顿号串 4 个以上名词；
    - 连环冒号；
    - 口语或省略式短语（如「后台现成」），要写完整的产品描述（如「自带管理后台」）；
    - 正文里写版本号小数点后的数字（环境要求里的最低版本除外：读者要据此装对版本）。

## 事实

- 不编功能、不编数字。命令、端口、版本、配置项以各仓 `main` 分支源码为准，写之前先查。
- 不链也不提 mugsun-uniappx-ui 源码仓（仓库暂未公开）。说到许可时写「MIT」，说到源码时写「源码仓库暂未公开」，不写「商业版」。
- 中英文同一批改，结构保持一致。
- 界面的名称统一写「管理后台」，不写「管理台」。英文写 admin console。

## 截图

- 视口 1440×900，设备像素比 2，存成 PNG。一屏的图是 2880×1800。
- 要截得比一屏长或短时，宽度保持 2880，高度按内容增减。
- 中文页的图用中文界面和亮色主题。
- 首页截图窗口另配深色图，文件名加 `-dark`，英文界面加 `-dark-en`，写在条目的 `dark` 字段里。
- 英文页有带 `-en` 的英文界面图就用它，没有就和中文页共用。
- 管理后台的标签栏只留「工作台」和当前页。
- 用演示数据截图，画面里不出现真实的手机号、密钥和令牌。
- 图放在 `public/screenshots/` 下按模块分的目录里，功能页的图放 `features/`。
- `public/readme/` 里的图还被各仓库的 README 外链，改名或删除前先查各仓库的 README。
- 替代文字写清画面里有什么，比如「服务监控页：五张指标卡片」。
- 界面改了就重截。页面不再引用的图从仓库里删掉。

## 版式

- 主题在 VitePress 默认主题上扩展，品牌色是橙色。不引入新的依赖。
- 样式分三个文件：`custom.css` 管颜色和手机框，`home.css` 管首页，`doc.css` 管文档页。
- 站点默认用深色，右上角可以切到浅色。两种模式版面相同，只换颜色变量。
- 深色的底接近黑色。面板用细的亮边，圆角 8 到 12px，鼠标移上去边会变成橙色。
- 首页首屏右边是一个可以拖动的地球。标题里的埋点、GIS、AI 三个词和下面的面板切换它显示的内容。
- 首页的截图放在第二屏的窗口里，可以切深色和浅色。
- 浅色模式下，首页的地球、命令块、终端、收尾一屏和页脚仍用深色。
- 橙色用在按钮、链接和当前项上，序号和图标也用橙色。
- 小标签、序号和仓库名用等宽字体。
- 首页的动效有地球、滚动出现和小图轮换。系统设了「减少动态效果」时全部停掉，内容照常显示。
- 首页的文字写在 `index.md` 的 frontmatter 里，由 `HomeLanding` 组件渲染。
- 首页会动的部分写在 `.vitepress/theme/home/` 下的脚本里，样式都在 `home.css`。
- 首页图里的标识符和数字要和文档一致。演示数字来自本地演示环境，旁边标「演示数据」。
- 英文首页的界面名称用管理后台英文界面的原名。
- 文档页有三种版式，见下表。不要为单个页面再写新的样式。
- 架构图用 `<ArchDiagram />` 组件，中英文文字都写在组件里。不用位图画架构图。
- 组件页的手机框和窄屏底栏（`DemoPhone`）是功能组件，保留。
- 概述页结构：h1 → 两三句引言 → 截图 → 「从哪里开始」→ 命令 → 功能表 → 限制 → 「下一步」。
- 操作页结构：h1 → 一句话 → 命令 → 一张结果截图 → 下一步。
- 功能页结构：h1 → 一两句引言 → 截图 → 「能做什么」→「启用」→「使用」→「注意事项」→「验证」→「下一步」。
- 功能没有界面时，功能页不放截图。
- 文档页右侧开目录。顶部导航分「指南 / 后端 / 管理后台 / 埋点 / 移动端 / 更多」，侧边栏按分区切换。

| 版式 | 写法 | 用在哪里 |
| --- | --- | --- |
| 链接卡片 | `<div class="ms-cards">` 里放一个链接列表 | 「从哪里开始」「下一步」 |
| 步骤 | `<div class="ms-steps">` 里放几个三级标题 | 要按顺序做的操作 |
| 流程 | `<div class="ms-flow">` 里放一个有序列表 | 数据经过的几个环节 |

开标签后面和 `</div>` 前面各留一个空行，里面的 Markdown 才会被解析。

卡片的每一项先写链接，再写一句话。三个环节的流程写 `ms-flow ms-flow--3`。
