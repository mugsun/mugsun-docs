# 文档写作规范

docs.mugsun.com 的中英文页面都按这份规范写。依据是 2026-10 对 VitePress、Vue、Element Plus、Vite、Astro、Supabase 等 10 个文档站的实测对比。

本文件放在 `docs/` 下，已加进 `srcExclude`，不会生成站点页面。

## 硬指标

| 项目 | 要求 |
| --- | --- |
| 首页字量 | 不超过 300 字（按渲染后页面上实际显示的汉字计数；英文按词数），不超过 2 屏 |
| 快速开始字量 | 1000 字以内 |
| 快速开始代码占比 | 40–70%（代码字符数 ÷ 正文字符数） |
| 段落长度 | 一段不超过 3 行，约 60 字；最长不超过 80 字 |
| 提示框 | 一页最多 3 个，每个一两句话 |
| 截图 | 一页一到两张 |

## 12 条规范

1. 首页只放 hero、3–4 张卡片，最多再加一段代码。模块表、适合与不适合、截图墙放「介绍」页。
2. hero 标题不超过 12 个字，副标题不超过 30 个字。写清楚它是什么、给谁用，不放版本号，不堆技术名词。
3. 卡片标题 2–6 个字，正文一句话，不超过 30 个字，不写版本号。
4. 快速开始第一屏就要有能复制的命令，命令前面最多两句话。
5. 快速开始控制在 1000 字以内，代码占一半左右。超出的内容拆到「部署」「配置」「常见问题」。
6. 一段不超过 3 行，一句只讲一件事。
7. 提示框（tip、warning）一页最多 3 个。可以不展开的内容放进 `::: details`。
8. 多种包管理器或多种写法用 `::: code-group`，不要连续摆几个代码块。
9. 截图只放「做完这一步应该看到的样子」。组件页用实时示例代替截图。
10. 标题写读者要做的动作，比如「安装」「启动后端」「上报第一条埋点」。不写「设计取舍」「能力」「全景」。
11. 正文不写 PR 编号、升级前后的口径差异、迁移 SQL。这些放「更新日志」和「升级指南」。
12. 禁用的写法：
    - 自造词，比如竖切、在位、装配、底座；
    - 「**加粗口号。** 解释」连着排；
    - 「不是……而是……」；
    - 用中点「·」或顿号串 4 个以上名词；
    - 连环冒号；
    - 口语或省略式短语（如「后台现成」），要写完整的产品描述（如「自带管理后台」）；
    - 正文里写版本号小数点后的数字（环境要求里的最低版本除外：读者要据此装对版本）。

## 事实

- 不编功能、不编数字。命令、端口、版本、配置项以各仓 `main` 分支源码为准，写之前先查。
- 不链也不提 mugsun-uniappx-ui 源码仓（仓库暂未公开）。说到许可时写「MIT」，说到源码时写「源码仓库暂未公开」，不写「商业版」。
- 中英文同一批改，结构保持一致。

## 版式

- 用 VitePress 默认主题，只覆盖品牌橙色。不加自定义卡片、截图网格之类的 CSS。
- 组件页的手机框和窄屏底栏（`DemoPhone`）是功能组件，保留。
- 页面结构：h1 → 一句话 → 命令 → 一张结果截图 → 下一步。
- 文档页右侧开目录。侧边栏按「开始 / 部署 / 后端 / 管理台 / 埋点 / 升级」分组。
