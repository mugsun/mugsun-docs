# GIS 与地图

「地理信息」是管理后台里的一组地图页面，用来看地图、画图形、管理图层和做空间分析。

这一页先列出有哪些页面，再讲怎么画出第一张图，最后说明按米计算的结果有多准。

![地图页，左边是画图工具，上边是场景、搜索和底图切换](/screenshots/gis/gis-workspace.png)

## 有哪些页面

点顶部导航的「地理信息」，左侧菜单有四个页面。另外两个页面不在菜单里。

| 页面 | 地址 | 用来做什么 |
| --- | --- | --- |
| 地图 | `/gis/workspace` | 画点线面，量距离和面积，叠加图层，保存成场景 |
| 示例 | `/gis/lab` | 13 个能直接运行的例子，每个都给出对应的接口 |
| 图层 | `/gis/layer` | 把数据存成图层，供地图页和其他模块叠加 |
| 底图 | `/gis/provider` | 配置底图服务商的密钥，见[底图配置](/pc/gis-basemap) |
| 空间分析 | `/gis/analyze` | 做缓冲、相交这类运算。从地图页的「更多 → 空间分析」进入 |
| 场景 | `/gis/scene` | 场景列表。平时在地图页左上角的下拉框里切换场景 |

- 二维地图用 OpenLayers，三维用 Cesium。
- 接口和存储都用 WGS84 坐标。用高德或百度底图时，页面显示前自动换算偏移。
- 底图瓦片由后端转发，密钥不进浏览器，见[底图瓦片代理安全](/pc/gis-tile-security)。
- 地图右下角显示底图的版权署名，例如「© 天地图」。
- 页面上没有审图号。公开展示地图时，要自己按规定标注。
- 这是可选模块，怎么关掉见[开关和权限](#switches)。

## 图层和数据导入

「图层」页管理存进库里的数据。点「入库图层」新建，「渲染」有五种。

| 渲染 | 数据从哪来 |
| --- | --- |
| 矢量 | 粘贴或导入的点、线和面 |
| 点热力 | 粘贴或导入的点，显示成热力 |
| XYZ | 填瓦片服务的地址 |
| WMS | 填服务地址和「WMS 图层名」 |
| 三维切片 | 填 `tileset.json` 的地址。内置的示例填 `hosted:demo-city` |

- 矢量数据可以是 GeoJSON，也可以是带 `lon` 和 `lat` 的数组，还可以是 WKT、CSV、KML 或 GPX。
- 坐标按 WGS84 入库，其他字段原样保留。
- 点「校验格式」先看能识别出多少个要素，再点「保存」。
- 一次最多导入 8000 个要素和 20 万个顶点，文本最多 2MB。
- 几何有问题时，保存会自动修复，并提示修复了几处。
- 在列表里点「叠加」，图层会叠到地图页上，可以随场景一起保存。
- 有 PostGIS 时，要素不少于 2000 个的图层改用矢量瓦片显示，只取当前视野里的数据。
- 改用矢量瓦片的图层不能导出，也没有整层的统计。

## 空间分析

从地图页的「更多 → 空间分析」进入。选一个「源图层」或者直接粘贴数据，再选一种运算，点「运算」。

| 运算 | 还要填什么 |
| --- | --- |
| 缓冲 | 「缓冲距离（米）」，1 到 200000 |
| 距离、相交、包含和差集 | 「对照图层」 |
| 简化 | 「简化容差」，0 到 1 |
| 其余六种 | 不用填 |

- 其余六种是质心、外包矩形和凸包，以及面积、长度和融合。
- 运算在服务端用 JTS 做。输入先统一成 WGS84 的 GeoJSON。
- 结果画在地图上。点「存为图层」存进图层库，点「叠加」带到地图页。
- 按米算的结果有多准，见下一节。

## 按米计算有多准 {#metric-accuracy}

缓冲、距离、面积和长度都按地面上的米来算，依据是 WGS84 椭球。走哪条路径，看功能和数据库。

| 功能 | 有 PostGIS 时 | 没有 PostGIS 时 |
| --- | --- | --- |
| 图层查询里的半径查询、最近邻和缓冲 | 在数据库里用 `geography` 计算 | Java 路径 |
| 空间分析里选了源图层、没有粘贴数据时的「缓冲」和「包含」 | 交给图层查询，在数据库里计算 | 交给图层查询的 Java 路径 |
| 空间分析的其他情况，以及带 `engine=java` 的请求 | Java 路径 | Java 路径 |

- 没有 PostGIS 的情况指 MySQL、达梦这类数据库。
- 地图页右上角的标签显示「PostGIS」或者「Java 回落」，表示数据库有没有 PostGIS。
- 图层查询接口和分析接口都接受 `engine=java`，强制走 Java 路径，用来诊断和对比。
- `engine=java` 只有平台超管能用，其他人带上它会返回 403。
- 分析接口带 `engine=java` 时不交给图层查询，整份入参在内存里分析。

### Java 路径怎么算

Java 路径建立在 GeographicLib 和 JTS 上。两个顶点之间的边按 WGS84 椭球上的测地线处理。

| 运算 | 做法 |
| --- | --- |
| 缓冲 | 以要素包络的中心做椭球方位等距投影，在平面上缓冲后投回 |
| 距离 | 以查询点为原点投影，求几何上的最近点，再用 GeographicLib 反算 |
| 面积 | 用 GeographicLib 的 `PolygonArea` 直接在椭球上算，外环减内环 |
| 长度 | 逐段测地距离求和 |

- GeographicLib 用的是 Karney 算法，和 PostGIS 的 `geography` 同源。边按测地线处理也和它一致。
- 缓冲在投影前和投回后，都沿测地线每 1 公里取点加密。
- 纬度的绝对值不小于 88° 时，缓冲的投影改以极点为原点。
- 距离算到顶点和边上的任意一点。点在面内时距离是 0。
- 面积和 PostGIS 的 `ST_Area(geography)` 一致。

### 误差有多大

下表是 Java 路径做缓冲的相对误差，点、线、面合在一起取范围。

| 位置 | 500 米缓冲 | 20 公里缓冲 | 200 公里缓冲 |
| --- | --- | --- | --- |
| 赤道 | 0 ～ +0.03% | −0.03% ～ 0 | −0.03% ～ 0 |
| 北京（39.9°N） | 0 ～ +0.03% | −0.03% ～ 0 | −0.03% ～ 0 |
| 72°N | 0 ～ +0.02% | −0.03% ～ 0 | −0.03% ～ 0 |
| 78°N | 0 ～ +0.02% | −0.03% ～ 0 | −0.03% ～ 0 |
| 86°N | 0 ～ +0.02% | −0.03% ～ 0 | −0.03% ～ 0 |
| 88°S | −0.02% ～ +0.03% | −0.04% ～ 0 | −0.05% ～ 0 |
| 88°–89.6° 的长边线和面 | −0.05% ～ +0.05% | −0.03% ～ 0 | 未测 |

- 量法是取缓冲边界上的每个顶点，算它到原要素的测地距离，再和设定的米数比较。
- 真值用 GeographicLib 算。
- 剩下的误差主要来自圆弧用折线近似，每 1/4 圆 32 段。

和 PostGIS 路径对照的结果如下。

| 对照项 | 相差 |
| --- | --- |
| 赤道、北京和 72°N 的点线面，缓冲距离 500 米到 200 公里 | −0.18% ～ +0.002% |
| 88°–89.6° 的线和面，缓冲距离 500 米到 5 公里 | −0.05% ～ +0.05% |
| 两条路径缓冲结果的面积 | −0.5% ～ +0.8% |
| 面积对照 `ST_Area(geography)`，含 60°×60° 和高纬 170° 宽的多边形 | 小于 10⁻¹⁵ |

- 前两行的量法是把同一个缓冲结果的外环顶点，用 `ST_Distance(geography)` 量到原要素。
- 缓冲面积的差别主要来自 PostGIS `ST_Buffer(geography)` 自身的投影近似。

::: warning 旧版本的偏差
早先的版本在 Web Mercator 平面上按米计算，没有做纬度修正。缓冲半径和距离按 cos(纬度) 缩小，面积按 cos²(纬度) 缩小。

北京的 500 米缓冲实际只有约 383 米，72°N 只有约 31%。升级后的精度见上表。
:::

## 特殊情况和限制 {#metric-limits}

极区和 180° 经线附近都照常计算，没有纬度限制。只有两种要素算不出来，页面会提示「已跳过 n 个要素」。

### 算不出来的两种要素 {#skipped}

这两种要素本身都没有包住极点，但结果没法用普通的经纬度面表示。

| 情况 | 原因 | 怎么办 |
| --- | --- | --- |
| 缓冲结果包住了极点 | 缓冲后盖住北极或南极，无法按普通的经纬度面输出 | 缩小缓冲距离，或者在极点附近把要素拆开 |
| 单个部分的经度跨度超过 180° | 接成连续经度后仍宽于 180°，或者缓冲结果绕地球一周，无法确定走向 | 先在 180° 处把要素拆开 |

遇到这两种要素时，不同的入口反应不同。

| 入口 | 反应 |
| --- | --- |
| 空间分析算单个几何 | 直接报错。带 `engine=java` 从源图层取出的几何也一样 |
| 图层的缓冲查询 | 跳过这些要素，其余照常返回。跳过的个数在响应的 `skipped` 里 |
| 图层的半径查询和最近邻 | 跳过宽于 180° 的要素，个数同样在 `skipped` 里 |
| 空间分析交给图层查询的「缓冲」和「包含」 | 响应同样带 `skipped` |
| 空间分析汇总面积和长度 | 宽于 180° 的要素不计入，个数在 `metrics.metricsSkipped` 里 |

- 跳过要素时后端记一条 WARN 日志。同一个图层的同一种操作，每分钟最多记一条。
- 包住极点的面不受这两条限制，照常缓冲和量距。
- 只是越过 180° 的缓冲不会被跳过，结果在 180° 处切开返回。
- 空几何的距离按无穷远算，半径查询不命中，最近邻排在最后。
- 空几何的缓冲结果为空，面积和长度是 0。

### 跨 180° 经线 {#antimeridian}

要素、查询范围和缓冲结果都可以越过 180° 经线，按 RFC 7946 的写法处理。

| 情况 | 怎么处理 |
| --- | --- |
| 要素的各部分分在 180° 两侧 | 先接成连续的经度，再算距离、面积和长度 |
| 缓冲结果越过 180° | 在 180° 处切开，返回 MultiPolygon，例如斐济附近的缓冲 |
| 范围查询的西经界大于东经界 | 当作跨 180° 的范围，拆成两个框查询，例如 `minLon=170&maxLon=-170` |
| 半径查询和最近邻的粗筛范围越过 180° | 拆成两个框分别筛，对侧的要素不会漏掉 |
| 库里的要素写成 `LINESTRING(179.9 0, -179.9 0)` 这样 | 当作跨 180° 的短线，不当作横跨全球的长线 |

- 判断要素是否跨 180°，看它的平面包络是否宽于 180°，并且把负经度加 360 后不再宽于 180°。
- 范围、相交、包含和半径查询里，这类要素在 0° 附近不会误命中，在 180° 附近能查到。
- 查询点靠近 180° 也能查，例如经度 179.9 能查到 -179.9 的要素。
- 量距离时，查询点换到和要素相同的经度范围，取离要素较近的那个位置。
- 表里那条短线离 (0, 0) 约 20004 公里，离 (179.95, 0.1) 约 11.1 公里。
- 半径查询和最近邻粗筛时，米换算成度留了余量。
- 范围查询的南纬界不小于北纬界时，仍然报错。
- 真的向东绕过大半个地球的宽要素，也会被当成跨 180° 的短要素。要表达它，请拆成多段。
- PostGIS 路径和 Java 路径的处理一致，存储的数据不变。

### 包住极点的面 {#polar}

把北极或南极包在里面的面，也能算面积、缓冲和距离。下面两种写法都算包住极点。

| 写法 | 例子 |
| --- | --- |
| 极冠，沿 ±180° 接到极点 | `POLYGON((-180 80, …, 180 80, 180 90, -180 90, -180 80))` |
| 绕极一圈，不含极点顶点 | `POLYGON((0 80, 90 80, 180 80, -90 80, 0 80))` |

- 判断依据是沿外环累计的经度约等于 ±360°，和 GeographicLib `PolygonArea` 的算法一致。
- 绕极一圈的环在入库时改写成第一种写法，并记一条 WARN 日志。
- 面积直接用 `PolygonArea` 在原来的环上算。
- 缓冲和距离改用以极点为原点的方位等距投影。点在面内时距离是 0。
- 缓冲结果按 RFC 7946 的极地切口写出，也就是沿 ±180° 接到极点。
- 形状不规则的面，缓冲结果是一个等纬度的极冠，边取缓冲后最南或最北的纬度。
- 这个极冠是近似值，不等于把原来的边界精确外扩。
- 有 PostGIS 时，这类面的缓冲也在 Java 里算，因为 `ST_Buffer(geography)` 会丢掉极点一侧。
- 只跨 180°、没有包住极点的面，缓冲仍然交给数据库的 `ST_Buffer`。
- 查询点在极区或极点上都可以查。

### 边按测地线算 {#geodesic-edges}

RFC 7946 把两个顶点之间的边看成经纬度平面上的直线，这里按椭球上的测地线算。同一个多边形的面积因此会有差别。

| 范围 | 面积相差 |
| --- | --- |
| 赤道 1°×1° | +0.003% |
| 北纬 30°–40° 的 10°×10° | +0.004% |
| 赤道 10°×10° | +0.25% |
| 北纬 60°–70° 的 10°×10° | −0.37% |
| 中国范围，73°–135°E、18°–54°N | −0.59% |
| 0°–60° 的 60°×60° | +2.27% |

- 上表用 GeographicLib 实测，把经纬度直边加密到 2 万个点，再和测地线边对比。
- 范围越大、越靠近赤道或高纬，差别越大。城市级范围的差别可以忽略。
- 高纬度上跨很多经度的长边会向极点弯。75°N 上从经度 0° 到 170° 的边，中段会弯到 89°N 附近。
- 这类要素的面积、长度和距离，以 PostGIS 的 `geography` 为准。
- PostGIS 路径的最近邻是近似的。它先按经纬度平面距离取候选，再按 `geography` 距离重新排序。
- 候选数是结果数的 10 倍，最少 100 个，最多 10000 个。
- 在高纬度、要素密集的图层里，真正最近的要素可能不在候选里。

### 数据库里的列和索引 {#migration}

有 PostGIS 时，跨 180° 的要素靠一个生成列和一个索引来查。升级数据库时注意下面几点。

| 对象 | 说明 |
| --- | --- |
| `gis_feature.wraps_antimeridian` | 布尔生成列，标记要素是否跨 180°。由数据库计算，应用不维护 |
| `idx_gis_feature_wrap` | 部分 GiST 索引，表达式是 `ST_ShiftLongitude(geom)`，只收跨 180° 且未删除的要素 |

- 加列的语句在迁移基线里。没有 PostGIS 或没有 `gis_feature` 表时，这一段跳过。
- 索引由 Java 迁移 V17 用 `CREATE INDEX CONCURRENTLY` 建，它不在事务里执行。
- Flyway 在主库上用会话级的锁，对应 `flyway.postgresql.transactional.lock=false`。
- 所以要直连 PostgreSQL，或者用 PgBouncer 的 session 模式。不能用 transaction 模式。
- 范围、相交、包含和半径查询，还有最近邻，都用到这个索引。
- 没有 PostGIS 时不用这一列和索引，Java 路径照旧。

## 窄屏和控件位置 {#layout}

| 页面 | 宽屏 | 宽度不超过 768px |
| --- | --- | --- |
| 地图 | 缩放按钮在左下角 | 顶部三组工具条各占一行，底部状态条占满一行，缩放按钮移到右上角 |
| 带左侧面板的页面 | 缩放按钮在面板右边，不会被面板盖住 | 底部的操作提示占满一行，点右边的 × 收起 |

- 窄屏下地图页的三行依次是视图和底图、场景和保存、搜索。「二维」和「三维」固定在最左边。
- 带左侧面板的页面有示例、图层和底图，还有场景和空间分析。
- 示例页底部没有操作提示。
- 操作提示收起后，重新进入页面会再出现。

## 埋点里的地图 {#track}

埋点分析有三个地方用到地图，数据来源不一样。

| 位置 | 显示什么 | 数据来源 |
| --- | --- | --- |
| 「数据概览」的地域分布 | 各地区的访问量 | 按 IP 判断的属地 |
| 「数据概览」的访问热力 | 访问位置的热力 | SDK 上报的精确坐标 |
| 「空间行为」页 | 热力格或明细点 | SDK 上报的精确坐标 |

- 精确坐标默认不采集。在「接入管理」里打开应用的「精确位置」后，SDK 会先征求用户的定位授权。
- 地图页「更多」里的「埋点热力」，叠加的也是这些精确坐标。
- 详细说明见[空间行为](/track/spatial)。

## 开关和权限 {#switches}

地理信息是可选模块，有三个开关，默认都是开的。

| 开关 | 在哪里设 | 关掉以后 |
| --- | --- | --- |
| `VITE_ENABLE_GIS` | 管理后台构建时的环境变量 | 打出来的包里没有地图页面 |
| `mugsun.gis.enabled` | 后端配置文件，或环境变量 `MUGSUN_GIS_ENABLED` | 后端不加载这个模块 |
| `gis.module.enabled` | 管理后台的参数管理 | 菜单隐藏，地图接口返回 404 |

每个页面和按钮都有权限码，在角色管理里勾选。

| 权限码 | 控制什么 |
| --- | --- |
| `gis:workspace:list` | 打开地图页 |
| `gis:scene:save` 和 `gis:scene:remove` | 保存和删除场景 |
| `gis:layer:list` | 打开图层页 |
| `gis:layer:save` 和 `gis:layer:remove` | 保存和删除图层 |
| `gis:analyze:run` | 做空间分析 |
| `gis:demo:list` | 打开示例页 |
| `gis:provider:list` | 打开底图页 |
| `gis:provider:save` 和 `gis:provider:remove` | 保存和清除底图配置 |

开关取值的完整规则见架构页的[两层开关](/guide/architecture#模块装配-两层开关)。
