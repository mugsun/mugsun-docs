# 行为验证码

管理台的登录、注册、忘记密码和短信发送接入了行为验证码。题型共五种：滑块（SLIDER）、旋转（ROTATE）、文字点选（WORD_CLICK）、图标点选（ICON_CLICK）、拼图还原（JIGSAW，2×2）。

题目由服务端出、由服务端判。出哪种题由服务端决定：每次取题时，服务端从租户启用的类型中随机选一种，前端不能指定。服务端配置见 [配置说明](/boot/configuration)。

## 前端行为

- 页面先调 `GET /api/auth/captcha/config` 判断是否需要验证码。返回的 `type` 只是提示，实际题型以 `challenge` 响应中的 `type` 为准。遇到前端不认识的题型时，回退到旧的数字验证码。
- 弹层是 `CaptchaDialog`，它根据 `type` 切换到滑块、旋转、点选或拼图面板。验证成功后拿到一次性的 `captchaToken`，随业务请求一起提交。
- 所有坐标都用显示像素，原点在底图左上角，服务端按 `bgWidth / bgDisplayWidth` 换算回原图像素。上报的 `bgDisplayWidth` 不小于 260：容器比 260px 窄时，弹层整体按比例缩放，不会上报更小的宽度。
- 旋转题的拖动条与底图等宽，按滑块左边缘的位移计算，拖到最右等于 360°。
- 点选题按提示顺序点击 3 个目标，点中的位置会显示序号，点序号可以撤销。点满 3 个后自动提交。
- 拼图题点击两块即可交换位置（也可以拖动交换），还原后点「完成」。

## 键盘操作

点击「改用键盘」会重新取题。键盘模式下只会出滑块或旋转题，用 ←/→ 调整，按住 Shift 可以大步移动，按 Enter 提交。旋转题每按一次转动服务端返回的 `keyboardStep` 度。

如果租户没有启用滑块和旋转，键盘取题会返回 `40015`。此时弹层提示改用鼠标或触屏，并提供「改用鼠标 / 触屏」按钮，不会自动重试。

## 错误处理

| 码 | 前端处理 |
| --- | --- |
| 40010 | 已过期，自动换一张 |
| 40011 | 未通过，抖动提示后自动换题（换题后题型可能变化）；verify 连接中断也按 40011 处理 |
| 40012 | 失败次数过多被锁定，按 `retryAfter` 倒计时，倒计时期间不能操作 |
| 40014 | 当前无需验证，直接提交业务请求 |
| 40015 | 键盘模式下没有可用题型，提示改用鼠标或触屏 |

## 开发期 mock

不连后端调试界面时，可以用 mock 模式启动，只需在命令行设置环境变量，不要写进 `.env` 文件：

```bash
VITE_CAPTCHA_MOCK=true pnpm dev
```

- 在 URL 上加 `?captchaType=ROTATE` 可以指定题型（仅 mock 模式有效）。
- 设置 `sessionStorage.captchaMockNoKeyboard = '1'` 可以模拟 40015。

mock 只在 `DEV` 模式下、且 `VITE_CAPTCHA_MOCK=true` 时才会加载，生产构建不包含 mock 代码。注意 mock 的旋转容差比服务端宽，判定结果以服务端为准。用 mock 模式录的截图或录屏须标注「前端 mock、服务端校验未接」。
