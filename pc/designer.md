# 设计器

管理后台里有四个设计器。这页讲两个流程设计器和 AI 应用编排怎么用，表单设计见[表单](/boot/features/form)。

## 有哪些设计器

| 设计器 | 入口 | 用来做什么 |
| --- | --- | --- |
| 流程设计器 | 「系统管理 → 流程定义」里的「设计流程」 | 按顺序排审批节点，可以绑定表单 |
| 图形流程设计器 | 「系统管理 → 流程设计」里的「图形设计流程」 | 画带分支和 AI 节点的审批流程 |
| 应用编排 | 「AI 中心 → AI 应用 → 机器人应用」里应用卡片上的「编排」 | 把大模型、知识库等节点连成一个 AI 应用 |
| 表单设计 | 「系统管理 → 表单设计」 | 拖拽出一张表单 |

- 流程要绑定表单，或者要按节点控制字段读写，用流程设计器。
- 流程里有条件分支、并行分支或 AI 预审，用图形流程设计器。
- 两个流程设计器发布的流程在同一个列表里，「流程定义」和「流程设计」两个页面都能看到。
- 两个流程设计器只有平台超级管理员能用。

## 流程设计器

打开「系统管理 → 流程定义」，点「设计流程」。这个按钮需要 `sys:flow:design` 权限。

<div class="ms-steps">

### 填编码和名称

「流程编码」填英文标识，例如 `purchase`。「流程名称」填给人看的名字。两项都必填。

### 绑定表单

「绑定表单」可以不选。选了以后，发起流程时要填这张表单，审批人办理时也会看到它。

### 添加审批节点

弹窗里默认有一个「部门审批」节点。点「+ 添加审批节点」继续加，流程按节点的排列顺序流转。

每个节点要填节点名称，并且至少选一个候选人。

### 发布

点「发布流程」。发布成功后提示「流程已发布」，流程出现在列表里，点「发起」就能用。

</div>

发起和审批的过程见[工作流](/boot/features/workflow)。

### 候选人怎么选 {#candidates}

两个流程设计器的候选人类型相同。

| 类型 | 谁来审批 |
| --- | --- |
| 角色 | 拥有这个角色的用户 |
| 部门 | 这个部门的用户 |
| 指定用户 | 选中的那个用户，可以按用户名或昵称搜索 |
| 发起人本人 | 发起这条流程的人 |
| 部门负责人 | 发起人所在部门的负责人 |

一个节点可以有多个候选人，点「+候选人」添加。

### 字段权限

流程绑定了表单以后，每个节点上会多出「字段权限」按钮。

- 每个表单字段可以设成「可写」「只读」或「隐藏」，默认是「可写」。
- 审批人办理这个节点时，表单按这里的设置显示。
- 换一张绑定的表单，已经设好的字段权限会清空。

## 图形流程设计器

![图形流程设计器里的一条请假审批流程](/screenshots/pc/flow-graph-designer.png)

打开「系统管理 → 流程设计」，点「图形设计流程」。这个按钮需要 `sys:flow:design-graph` 权限。

设计器是一个全屏弹窗。先填「流程编码」和「流程名称」，「分类」可以不填。

画布上默认是「开始 → 审批 → 结束」。点两个节点之间的「+」，选择要插入的节点。

### 节点类型

| 节点 | 作用 | 要设置的内容 |
| --- | --- | --- |
| 审批节点 | 等候选人审批 | 节点名称、候选人和签署方式 |
| 条件分支 | 按流程变量走其中一条分支 | 每条分支的名称和条件 |
| 并行分支 | 几条分支同时进行，全部走完再往下 | 至少两条分支 |
| AI 节点 | 运行一个 AI 应用，把结论写进流程变量 | 应用、超时时间、失败处理和变量映射 |

审批节点的签署方式有三种。候选人的选法见[候选人怎么选](#candidates)。

| 签署方式 | 含义 |
| --- | --- |
| 或签 | 任意一个候选人通过，节点就通过 |
| 会签 | 所有候选人都通过，节点才通过 |
| 票签 | 超过一半的候选人通过，节点就通过 |

### 条件分支

新插入的条件分支带两条分支：「分支一」和「否则」。点「+ 分支」可以再加。

- 每条分支可以写多个条件，点「+条件」添加。
- 一个条件由变量、比较方式和值组成，变量是流程变量的名字。
- 条件多于一个时，选「且」或「或」决定怎么组合。
- 勾上「否则（默认分支）」的分支不用写条件。其他分支都不满足时走这一条。
- 变量名以字母或下划线开头，只能包含字母、数字和下划线。
- 值里不能有 `|`、`@@` 和换行。

| 比较方式 | 用在哪 |
| --- | --- |
| 等于 / 不等于 | 判断值是否相同 |
| 大于 / 大于等于 / 小于 / 小于等于 | 比较大小 |
| 包含 / 不包含 | 判断文本里有没有某一段 |

### AI 节点

流程走到 AI 节点时自动运行一个 AI 应用，常用来做预审。

| 设置项 | 说明 |
| --- | --- |
| 「AI 应用」 | 当前租户已启用的工作流或对话流程应用。列表不对时点「刷新」 |
| 「超时」 | 1000 到 300000 毫秒，默认 120000 |
| 「失败时」 | 选「驳回上一节点」或「停在本节点」，也可以转交给某个角色 |
| 「入参映射」 | 把哪些流程变量传给应用。这一项必须有，但可以一行都不加 |
| 「出参映射」 | 把应用的输出写回哪些流程变量 |

- 提示词在 AI 应用里维护，这里只选应用和变量映射。
- 应用新建后默认是启用的。下拉框里每种类型最多列出 100 个应用。
- 每个字段的含义和失败后的处理，见[工作流的 AI 预审](/boot/features/workflow#ai-approval)。

### 发布流程

点「发布流程」。设计器先检查一遍，有问题时提示要改哪个节点：

- 流程编码或名称没有填。
- 一个节点都没有。
- 审批节点没有选候选人。
- 条件分支里有分支既没写条件，也没勾「否则」。
- 并行分支少于两条。
- AI 节点没有选应用。

检查通过后流程直接发布，提示「流程已发布」。设计器没有草稿，点「取消」或关掉弹窗，画好的内容不会保留。

### 管理已发布的流程

「流程设计」页的列表里，一个版本占一行。

| 操作 | 作用 |
| --- | --- |
| 「停用」 | 这个流程不能再发起新的实例。点「启用」恢复 |
| 「复制新版本」 | 复制出一个版本号加一的版本，状态是「未发布」 |
| 「删除」 | 删掉这一个版本。已经有人发起过的流程不能删，请改为停用 |

- 这三个操作需要 `sys:flow:definition` 权限。
- 用同一个编码再发布一次，会多出一个新版本，原来的版本变成「未发布」。
- 设计器每次打开都是一条新流程，不能打开已有的流程接着改。
- 要改一条流程，用同一个编码重新画一遍再发布。

## AI 应用编排

![应用编排的画布和右侧的节点属性](/screenshots/pc/ai-app-orchestration.png)

打开「AI 中心 → AI 应用 → 机器人应用」，点「新建应用」填名称、类型和描述，再点应用卡片上的「编排」。

| 应用类型 | 编排页的内容 |
| --- | --- |
| 工作流 | 画布。新建时已经连好「开始 → 大模型 → 结束」 |
| 对话流程 | 画布。新建时已经连好「开始 → 大模型 → 结束」 |
| 文本生成 | 画布。新建时已经连好「开始 → 文本 → 结束」 |
| 对话助手 | 没有画布，只有一张表单，填模型参数、系统提示词、开场白和预设问题 |

### 在画布上操作

- 从左侧把节点拖到画布上。
- 从一个节点右边的圆点拖到另一个节点左边的圆点，连出一条带箭头的线。
- 点一下节点，在右侧「节点属性」里改名称和这个节点的设置。
- 选中节点或连线后按 Backspace 删除。节点也可以用「节点属性」里的「删除节点」删。
- 一个流程只能有一个「开始」和一个「结束」。
- 节点不能连到自己，两个节点之间同一个方向只能有一条线。

### 节点

| 节点 | 类型 | 作用 | 「节点属性」里能填的 |
| --- | --- | --- | --- |
| 开始 | `start` | 流程入口 | 名称 |
| 结束 | `end` | 流程出口，给出最终结果 | 名称 |
| 分支 | `switch` | 判断表达式的结果，决定下一步走哪个节点 | 表达式和期望值 |
| 循环 | `foreach` | 对数组里的每个元素运行一遍循环体 | 见[循环和并行节点](#ai-flow-control) |
| 并行 | `parallel` | 同时运行几条分支 | 见[循环和并行节点](#ai-flow-control) |
| 大模型 | `llm` | 把提示词发给大模型 | 提示词 |
| 知识库 | `rag` | 在知识库里检索 | 知识库 ID |
| 问题分类 | `question` | 把输入归到某个类别 | 只有名称 |
| 信息提取 | `extract` | 从文本里提取字段 | 提示词 |
| 内容优化 | `optimize` | 润色、改写、翻译或写摘要 | 提示词 |
| 数据库 | `db` | 运行一条只读查询 | SQL |
| 代码 | `code` | 目前不会运行代码 | 只有名称 |
| 文本 | `text` | 按模板拼出一段文本 | 模板 |
| 变量更新 | `updateVar` | 修改变量的值 | 只有名称 |
| HTTP | `http` | 请求一个网址 | URL |
| MCP | `mcp` | 调用一个 MCP 工具 | 只有名称 |
| 通知 | `notice` | 通过消息渠道发通知 | 只有名称 |

- 除了「开始」和「结束」，每个节点都能填「输出变量」，把这个节点的结果存进一个变量。
- 提示词和模板里用 <code v-pre>{{变量名}}</code> 引用变量。
- 用户的输入在变量 `input` 里，上一个节点的结果在变量 `output` 里。

### 保存、运行和分享

| 按钮 | 作用 | 需要的权限 |
| --- | --- | --- |
| 「保存」 | 检查通过后保存画布上的内容 | `ai:app:design` |
| 「运行」 | 用固定的输入「你好」运行一次，结果显示在画布下面 | `ai:app:run` |
| 「分享」 | 生成一个分享链接 | `ai:app:publish` |
| 「导出 DSL」 | 把画布上的内容下载成 `ai-app-<应用编号>.json` | 不需要 |

保存前会检查三件事：

- 「开始」和「结束」各有一个。
- 每个节点都连了线。循环体和并行分支里选中的节点不用连线。
- 循环和并行节点的设置完整。

::: warning 先保存再运行，先保存再离开
「运行」跑的是上一次保存的内容，画布上没保存的改动不算。离开编排页时页面不会提醒，没保存的改动就没有了。
:::

## 循环和并行节点 {#ai-flow-control}

「循环」和「并行」是两个控制节点。它们要运行的节点在「节点属性」里选，不靠连线。

先把要用的节点拖到画布上，再点控制节点，在右侧选中它们。被选中的节点不用连线。

### 循环

| 设置项 | 说明 |
| --- | --- |
| 「输入路径」 | 必填。数组所在的变量名或点分路径，例如 `items`、`data.list` |
| 「元素变量」和「下标变量」 | 当前元素和下标存进哪两个变量，默认是 `item` 和 `index` |
| 「最大迭代」 | 最多运行多少轮，1 到 100，默认 20 |
| 「超时(ms)」 | 整个节点的超时时间，1000 到 300000，默认 120000 |
| 「聚合方式」 | 各轮的结果怎么汇总，选「数组」「末次」或「不聚合」 |
| 「项失败策略」 | 某一轮失败后「继续」还是「中止」 |
| 「循环体节点」 | 每一轮要运行的节点，按运行顺序选 |
| 「输出变量」 | 汇总结果存进哪个变量，默认是 `foreachResults` |

### 并行

| 设置项 | 说明 |
| --- | --- |
| 「并行分支」 | 至少两条。点「加分支」和「删分支」增减 |
| 「分支 ID」 | 分支的编号，同一个节点里不能重复，默认是 `b1`、`b2` |
| 「分支名」 | 给人看的名字 |
| 「分支节点」 | 这条分支要依次运行的节点 |
| 「输出变量」 | 这条分支的结果存进哪个变量，默认是 `branch_<分支 ID>` |
| 「分支上限」 | 最多几条分支，2 到 16，默认 8 |
| 「超时(ms)」 | 整个节点的超时时间，1000 到 300000，默认 120000 |
| 「等待全部」和「分支失败策略」 | 已锁定。所有分支结束后才往下走，一条分支失败不影响其他分支 |

### 两个节点共同的规则

- 循环体和分支里不能再放「循环」或「并行」。
- 点「运行」后，结果下面会多出「控制节点结果」，列出每一轮和每条分支的情况。
- 「已截断」表示数组比「最大迭代」长，只处理了前面的元素。
- 「部分成功」表示并行节点里有分支失败。

字段的默认值、运行规则和错误码，见[工作流](/boot/features/workflow#ai-flow-control)。

## 应用编排目前的限制

应用运行时从「开始」出发，沿着连线一个节点一个节点往下走，最多走 200 步。

- 一个节点连出多条线时，只走第一条。只有「分支」节点会按判断结果选下一个节点。
- 「代码」节点不会运行代码，只返回一句说明。
- 「信息提取」和「内容优化」运行时不读「节点属性」里的提示词。
- 有些节点运行时要用的字段，「节点属性」里还没有，见下表。

| 节点 | 「节点属性」里没有的字段 |
| --- | --- |
| 数据库 | `datasourceId`：数据源编号，必填 |
| MCP | `mcpToolId`：MCP 工具编号，必填 |
| 通知 | `channelId`：消息渠道编号，必填 |
| 问题分类 | `categories`：类别列表 |
| 变量更新 | `operations`：要做的修改 |
| 分支 | 下游节点的 `case`：和判断结果对上的那个节点被选中 |

这些字段要直接写进 DSL：

1. 在画布上搭好流程并保存，点「导出 DSL」。
2. 在导出的文件里，把字段加到对应节点的 `data` 里。
3. 把改好的内容作为 `dsl` 字符串提交给保存接口，需要 `ai:app:design` 权限。

```http
POST /system/ai/app/dsl/save?id=<应用编号>
Content-Type: application/json

{ "dsl": "<改好的 DSL，JSON 字符串>" }
```

之后再在画布上保存，这些字段会保留。
