# 报错速查

本页收录接口返回、启动日志和数据库迁移里常见的报错。报错原文取自 boot、core、pc 主干的源码，每条写明原因和处理办法。

报错里会变的部分用 `…` 表示，例如锁定的分钟数、字段名。

## 接口返回的状态码

后端的接口都返回统一结构 `{"code":…,"msg":…}`。这一节标题里的数字是 HTTP 状态码。

### 400 操作失败

```text
操作失败
```

请求参数类型不对、缺少必填参数，或请求体不是合法的 JSON 时，返回 HTTP 400 和这条提示。

请检查请求参数和请求体的格式。参数校验不通过时，`msg` 会换成字段上配置的校验提示。

### 400 数据已存在

```text
数据已存在，请勿重复提交
```

插入或更新触发了唯一约束，例如重复的账号、编号。这条提示不带字段名，也不写入错误日志表。

请换一个没有用过的值再提交。要看是哪个字段，把日志级别开到 DEBUG，日志里有完整的 SQL。

### 401 请求未授权

```text
请求未授权
```

没有带登录令牌，或令牌已过期、已被踢下线。管理后台收到后会退出登录，并提示「未授权访问，请重新登录」。

请重新登录。令牌只存在当前标签页，新开标签页也要重新登录。

### 403 没有访问权限

```text
没有访问权限
```

当前角色没有这个接口要求的权限标识或角色。

请让管理员在「角色管理」里给当前角色勾选对应的菜单或按钮权限。

### 403 没有接口的访问权限

```text
没有接口「…」的访问权限。请让管理员在接口权限中把该路径授给当前角色
```

这个接口配置了接口权限规则，当前角色没有被授予该路径。

请按提示在「接口权限」里把该路径授给当前角色。

### 403 平台级资源

```text
仅平台超管可访问平台级资源
```

普通租户的账号访问了只对平台开放的功能，例如定时任务、报表、存储配置。

请用平台租户 `000000` 下的超级管理员账号登录后再操作。

### 403 演示环境只读

```text
演示环境只读
```

这套环境开了只读演示模式，会改动数据的请求一律拒绝。响应里另有 `errorCode`，值是 `DEMO_READONLY`。

这是预期的结果。想改数据，请在本机启动一套，见[在线演示](/demo#local)。其他拒绝码见[只读演示模式](/boot/demo-mode#responses)。

### 404 资源不存在

```text
资源不存在
```

请求的路径不存在，常见于地址拼错，或者对应的模块没有启用。

请核对接口路径。GIS、AI 等模块关闭时，它们的接口也不存在。

### 405 请求方法不允许

```text
请求方法不允许
```

用错了 HTTP 方法，例如该用 POST 的接口发了 GET。

请按接口文档使用正确的方法。

### 500 服务器内部异常

```text
服务器内部异常
```

后端出现了未处理的异常。具体原因只写在服务端日志里，日志里有一行「系统未捕获异常」和完整堆栈。

请按响应头 `X-Trace-Id` 的值到服务端日志查找对应的堆栈。boot 还会把这条错误写入「错误日志」。

## 验证码

验证码的错误都是 HTTP 200，`code` 是下面的业务码。业务码定义在 boot 的 `CaptchaCodes`。

### 40010 验证已过期

```text
验证已过期，请重新验证
```

验证码题目或验证通过后拿到的 `captchaToken` 已经过期。

请重新取题并完成验证。

### 40011 验证未通过

```text
验证未通过，请再试一次
```

拖动位置、旋转角度或点选顺序不对。为防止探测，所有失败都返回同一条提示。

请重新完成验证。

### 40012 尝试次数过多

```text
尝试次数过多，请稍后再试
```

同一来源短时间内验证失败太多次，触发了限流。

请等一会儿再试。响应里的 `data.retryAfter` 是需要等待的秒数。

### 40013 请先完成安全验证

```text
请先完成安全验证
```

验证码已开启，但登录、注册或发送验证码的请求没有带 `captchaToken`。旧前端仍调用已移除的 `GET /auth/captcha` 时也会出现。

请先走 `/auth/captcha/challenge` 和 `/auth/captcha/verify` 拿到 `captchaToken`，再放进请求体。

升级说明见[后端升级指南](/boot/upgrade#移除旧的数字图形验证码)。

### 40014 当前无需安全验证

```text
当前无需安全验证
```

当前租户关闭了验证码，前端却仍然去取题。

前端应先调用 `GET /auth/captcha/config`，按返回结果决定是否显示验证码。

### 40015 未启用无障碍验证方式

```text
未启用无障碍验证方式
```

用键盘方式取题，但租户没有启用滑块或旋转题型。键盘方式只支持这两种题型。

请在租户的验证码设置里至少启用滑块或旋转中的一种。

### 40016 验证方式暂不可用

```text
验证方式暂不可用，请联系管理员
```

租户启用的题型全部不可用，例如只启用了图标点选，但图标清单缺失。

请在租户的验证码设置里再启用一种题型，或补齐图标资源。

## 登录与账号

### 账号或密码错误

```text
账号或密码错误。请核对账号和密码后再登录
```

账号不存在或密码不对。为防止探测账号是否存在，两种情况返回同一条提示。

请核对账号和密码。连续输错会触发锁定。

### 账号已锁定

```text
账号已锁定，请 … 分钟后再试
账号已锁定，请联系管理员解锁
账号已锁定：…。请 … 分钟后再试，或联系管理员解锁
账号已锁定：…。请联系管理员解锁
```

连续输错密码达到安全策略设定的次数后，账号被临时锁定，提示里带剩余的分钟数。

管理员手动锁定时，提示里带管理员填写的原因。锁定没有期限时，提示联系管理员解锁。

请等锁定时间过去再登录，或让管理员在「用户管理」里解锁。

### 账号已停用

```text
账号已停用，请联系管理员
```

账号被管理员停用。

请让管理员在「用户管理」里把账号改为启用。

### 登录已失效

```text
登录已失效，请重新登录
```

当前会话已经失效，例如令牌过期或被踢下线后又调用了需要登录的接口。

请重新登录。

### 租户账号数已达上限

```text
租户账号数已达上限（…），请联系管理员开通
```

新建用户时，租户下的账号数已经达到租户设置的上限。

请让平台管理员在「租户管理」里调高这个租户的账号上限。

## 接口加密

标了 `@ApiDecrypt` 的接口只接受加密的请求体。这一节的报错都是 HTTP 200，`code` 是 400。

### 请求体没有加密

```text
请求体须为加密报文
缺少加密字段 encryptData
```

请求体不是合法的 JSON，或者 JSON 里没有 `encryptData` 字段。

请把请求体写成 `{"encryptData":"…"}`，值是加密后的密文。密文的格式见[密钥管理](/boot/crypto-keys#api-key-format)。

### 加密报文解密失败

```text
加密报文解密失败
```

密文用的密钥和后端现在的密钥对不上，或者密文被改过、格式不对。几种情况返回同一条提示。

在管理后台里遇到时，刷新页面让它重新取一次密钥。后端重启后换了密钥的原因见[常见问题](/guide/faq#transport-key)。

## 启动与配置 {#startup}

以下报错来自配置不对。除了最后一条，都出现在启动日志里，应用会直接退出。

关闭国密、关闭开放接口签名引起的拒绝启动，见[会拒绝启动的配置](/boot/configuration#会拒绝启动的配置)。

### 未配置 SM4 字段加密密钥

```text
未配置 SM4 字段加密密钥 MUGSUN_SM4_KEY，拒绝启动；本地开发用 dev profile（设 mugsun.crypto.sm4-local-key-file）
```

没有配置字段加密密钥。

本地开发时加上 `--spring.profiles.active=dev` 启动，会自动生成本地密钥文件。

生产环境请用 `openssl rand -hex 16` 生成密钥，配置到 `MUGSUN_SM4_KEY`。

### SM4 密钥格式不对

```text
MUGSUN_SM4_KEY 格式不对：须为 32 位 hex、解码后 16 字节的标准 base64，或过渡期的 16 字符旧写法；不补零不截断，拒绝启动
```

密钥长度或编码不对。

请改为 32 位 hex，例如用 `openssl rand -hex 16` 生成的值。

### SM4 密钥解不开已有数据

```text
MUGSUN_SM4_KEY 解不开库里已有的加密数据（…），拒绝启动。可能是换了密钥没迁移，或旧部署配的是 32 位 hex / 24 位 base64（旧版只取前 16 个字符）：请按文档「迁移」设 MUGSUN_SM4_OLD_KEY_LEGACY_PADDED=true 跑 Sm4KeyMigrationTool，或填回原来的密钥
```

启动自检时，现在的密钥解不开库里已经加密的字段。通常是换了密钥但没有迁移数据。

请填回原来的密钥。确实要换密钥时，按[迁移旧数据](/boot/crypto-keys#migrate)的步骤操作。

### 接口传输密钥被拒绝

```text
MUGSUN_API_KEY 等于已删除的旧内置默认值，拒绝启动：请换成新密钥（openssl rand -hex 16），或删掉该配置让系统自动生成
MUGSUN_API_KEY 格式不对：须为 32 位 hex，或带填充的标准 base64 且解码后正好 16 字节，拒绝启动
```

第一条是配置的值等于旧版本内置的默认密钥，第二条是长度或编码不对。

删掉 `MUGSUN_API_KEY` 这项配置，后端会自动生成并保存密钥。要自己指定，就用 `openssl rand -hex 16` 生成。

多实例要用同一个密钥，见[接口传输密钥](/boot/crypto-keys#接口传输密钥)。

### 缺少初始口令

```text
生产环境必须注入初始口令（环境变量 MUGSUN_INIT_PASSWORD 或配置 mugsun.security.init-password），禁止使用内置默认口令启动；本地自测请显式激活 dev profile
```

按生产环境启动，但没有配置初始口令。没有带 `dev` 这类开发 profile 时，也按生产环境处理。

生产环境请配置 `MUGSUN_INIT_PASSWORD`。本地自测请加上 `--spring.profiles.active=dev`。

### 缺少 SM2 传输密钥

```text
strict-keys 模式：未注入 SM2 传输密钥（MUGSUN_SM2_PRIVATE_KEY/MUGSUN_SM2_PUBLIC_KEY），拒绝启动
```

`prod` profile 会打开 `strict-keys`，这时 SM2 传输密钥对必须配置。

请配置报错里的两个环境变量，生成办法见[生成密钥](/boot/crypto-keys#生成密钥)。

审计签名密钥没配时不会拒绝启动，后端自动生成到 `~/.mugsun/audit-sign-sm2.key`，并打一条 WARN 日志。

### 本地文件签名密钥

```text
prod 开启了本地存储直出（x-file-storage local-plus enable-access=true），必须配置 mugsun.file.local-access.sign-secret（MUGSUN_FILE_SIGN_SECRET，至少 32 字符）
prod 开启了本地存储直出，mugsun.file.local-access.sign-secret（MUGSUN_FILE_SIGN_SECRET）至少 32 字符，当前 … 字符
mugsun.file.local-access.sign-secret 至少需要 32 个字符
```

用本地存储提供下载时，要用一个签名密钥来生成下载链接。`prod` 下必须配置，长度不到 32 个字符也会被拒绝。

请配置不少于 32 个字符的 `MUGSUN_FILE_SIGN_SECRET`。多实例要用同一个值。

### 生产环境不能用内存存储

```text
mugsun.captcha.store=memory 不能用于生产，请改为 redis
mugsun.login-lock.store=memory 不能用于生产，请改为 redis
```

验证码和登录锁定的内存存储只在单个实例内有效，按生产环境启动时不允许使用。

请删掉报错里的那项配置，或把值改为 `redis`。

### 缺少前端地址

```text
未配置 mugsun.web.front-url（环境变量 MUGSUN_FRONT_URL），无法跳转 OAuth 同意页
mugsun.web.front-url 必须是 http/https 绝对地址：…
```

这一条不在启动时报。访问 OAuth 授权地址时接口返回 500，上面的原文写在服务端日志里。

开放平台的 OAuth 授权要跳转到管理后台的同意页，所以后端要知道管理后台的地址。

请把 `MUGSUN_FRONT_URL` 设为管理后台的完整地址，例如 `https://admin.example.com`。

## 数据库迁移

### 迁移校验和不一致

```text
Migration checksum mismatch for migration version 1
```

开发库是用较早的 `main` 分支建的，库里记的是旧版 V1 脚本的校验和。

处理办法见[常见问题](/guide/faq#checksum)。

### V7 升级中止

```text
V7 升级中止：sys_user 有 … 组同租户重复手机号（未删除用户），手机号唯一索引建不了。…
```

只出现在 openGauss 和达梦。库里有同一租户下重复的手机号，唯一索引建不了。

请按[同租户重复手机号](/boot/upgrade#同租户重复手机号)查出并处理重复，再重新执行迁移。

### V11 升级中止

```text
V11 升级中止：sys_tenant 有 … 个租户编号被重复使用（含已删除行），全量唯一索引建不了。…
```

租户编号被重复使用过，包括已删除的租户。

请按[租户编号被复用](/boot/upgrade#v11)查出并处理复用的编号，再重新执行迁移。

## 管理后台提示

后端的响应里带 `msg` 时，管理后台直接显示 `msg`，也就是前面各节的原文。401 除外，固定显示下表第一行。

响应里没有 `msg` 时，管理后台按 HTTP 状态码显示下面这些提示。文案在 pc 的 `src/locales/langs/zh.json`。

| 提示 | 什么时候出现 | 处理 |
| --- | --- | --- |
| 未授权访问，请重新登录 | 后端返回 401 | 重新登录 |
| 禁止访问该资源 | 收到 403，响应里没有 `msg` | 多半是网关拦下的，检查网关的访问限制 |
| 请求的资源不存在 | 收到 404，响应里没有 `msg` | 核对接口地址和网关的转发路径 |
| 服务器内部错误，请稍后重试 | 收到 500，响应里没有 `msg` | 查网关和后端的日志 |
| 网关错误，请稍后重试 | 网关返回 502 | 确认后端已启动、反向代理地址正确 |
| 服务暂时不可用，请稍后重试 | 网关返回 503 | 后端在重启或过载，稍后再试 |
| 网关超时，请稍后重试 | 网关返回 504 | 检查慢接口，或调大代理超时 |
| 网络连接异常，请检查网络连接 | 请求没有收到任何响应 | 检查网络、后端地址和跨域配置 |
