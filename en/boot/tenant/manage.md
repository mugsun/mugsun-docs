# Tenants and plans

The platform super admin maintains tenants and plans under the Tenant Operations menu of the admin console.

![The tenant list: one row per tenant with its plan, account limit, status and expiry](/screenshots/tenant/tenant-list.png)

## Create a tenant

Open Tenant Operations → Tenants and click New Tenant. Fill in the name, contact, account limit, expiry time and plan.

On save, the system generates a 6-digit tenant code and creates the following defaults for the tenant:

- a department with the same name as the tenant;
- a default post with the code `default`;
- an admin role with the code `admin` and the data scope "all data";
- an admin user with the username `admin`.

After saving, a dialog titled "Tenant created (password shown once)" shows the tenant code, the admin account and a one-time password.

The password is random and shown only this once, so copy it right away and hand it over. When you create a tenant through the API, it is the `initialPassword` field of the response.

On first sign-in the admin is taken to User Center and must change this password before using anything else.

A tenant admin signs in with the tenant code, username and password on the sign-in page. Leaving the tenant code empty means the platform tenant.

## Disable, expiry and account limit

- After a tenant is disabled, its users cannot sign in. Users who are already signed in are rejected on their next call to an endpoint under `/system`.
- Once the expiry time passes, the tenant behaves as if it were disabled.
- An account limit of `-1` means no limit. When the limit is reached, adding a user asks you to contact the administrator.

The platform tenant cannot be disabled or deleted. Deleting any other tenant also soft-deletes its users, departments, posts and roles.

## Plans

A plan limits which features a tenant can use. Create a plan under Tenant Operations → Tenant Packages, select its feature menus, and then choose the plan on the tenant.

The plan is enforced on the server, not only by hiding menus.

When a tenant calls an endpoint outside its plan, the response is 403 with a message that the feature is not in the plan.

Changes to a plan or tenant made in the admin console take effect immediately. A tenant without a plan is not restricted.

![The plan list: one row per plan with its number of menus, status and remark](/screenshots/tenant/tenant-package.png)

## Platform endpoints

Endpoints for tenants, plans, tenant data sources, online users, storage settings, scheduled jobs and other platform resources are open only to the platform super admin. Menus, dictionaries and parameters are global settings; tenants can read them but cannot change them.

When the `X-Tenant-Id` request header differs from the tenant of the login session, the request is rejected with a cross-tenant access error.

## Verify

After you create a tenant on a plan that allows only users and departments, the list shows a new row with a code generated by the system, as in the screenshot at the top.

Check the tenant and its defaults with these queries. Replace `226994` with the actual tenant code:

```sql
SELECT tenant_code, tenant_name, status, account_count, package_id
FROM sys_tenant
WHERE is_deleted = 0
ORDER BY tenant_code;

SELECT 'dept' AS kind, dept_name AS name FROM sys_dept WHERE tenant_id = '226994' AND is_deleted = 0
UNION ALL SELECT 'post', post_name FROM sys_post WHERE tenant_id = '226994' AND is_deleted = 0
UNION ALL SELECT 'role', role_code FROM sys_role WHERE tenant_id = '226994' AND is_deleted = 0
UNION ALL SELECT 'user', username FROM sys_user WHERE tenant_id = '226994' AND is_deleted = 0;
```

The second query returns four rows: the department named after the tenant, the default post, the role `admin` and the user `admin`. Then look at the plan bound to each tenant:

```sql
SELECT t.tenant_code, p.name, p.menu_keys
FROM sys_tenant t
LEFT JOIN sys_tenant_package p ON p.id = t.package_id AND p.is_deleted = 0
WHERE t.is_deleted = 0
ORDER BY t.tenant_code;
```

The plan's `menu_keys` is `User,Dept`. Now call the API as that tenant's admin to check that the plan is enforced on the server.

Sign in to the admin console with the tenant code and the admin account, and change the one-time password first.

Then copy the request header as described in [Get a token](/en/boot/tutorial/first-api#get-a-token) and store it in `TOKEN`:

```bash
TOKEN='<the Authorization value you copied>'
curl -s "http://localhost:8080/system/user/page?pageNum=1&pageSize=10" -H "Authorization: $TOKEN"
curl -s "http://localhost:8080/system/role/page?pageNum=1&pageSize=10" -H "Authorization: $TOKEN"
```

The user list returns the tenant's single admin. The role list returns code 403 with the message that the feature is not in the plan.
